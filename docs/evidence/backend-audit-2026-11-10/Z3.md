# Backend audit round 5, lane Z3: the engine boundary (10 Nov 2026)

Base `565a03ff2`. Scope: `apps/api/engine/**`, `apps/voice-runtime/**`, the call lifecycle
from webhook to `calls` row, the poller, `/v1/worker/engine-actions/**` and
`/v1/worker/engine-lookups/**`, and the conformance suite.

## Fixed

### Z3-01 (P1, money and call record): a call taken before its agent's route was retired was dropped as "unmapped"

- **Where.**
  - `apps/workers/pipeline.py::_ingest_stages` and `::_pipeline_settled` resolved a call's
    tenant only through `_resolve_agent`, which reads `engine_agent_routes ... AND active`.
  - Two paths retire a route while its last calls' results are still on their way:
    - `apps/workers/engine_workspaces.py::retire_moved_engine_agent`, queued by the publish
      that recreates an agent in its client's own workspace (D-693). It waits only while
      `has_live_call` is true, then deletes the old agent's webhook and sets the route
      inactive.
    - `apps/api/agents/experiments.py` (conclude), which switches the arms' routes off in
      the concluding transaction.
- **Vendor timing.** `call.completed` is sent the moment a call ends. `call.analysed`
  follows once the call has been read: the analysis waits up to five seconds for
  `call.completed`, and a retried delivery can arrive later still
  (`thinnest-findings/mirror/snapshots/2026-10-29/pages/api-reference/webhooks.md:83-84,
  405-409`). A call that ended just before the retire job ran is no longer live, so the job
  goes ahead.
- **Failure scenario.**
  1. An inbound call on the old copy ends.
  2. The retire job runs seconds later, deletes the webhook and switches the route off.
  3. The signed delivery has no active secret (`signed_intake.signing_secret`). The poller's
     listing row, or the outstanding-call probe for a row `call.completed` already wrote,
     reaches `_ingest_stages`. That answers `unmapped` and raises
     `engine_agent_route_withdrawn` ("release it with the telephony provider"), which is
     the wrong remedy.
  4. The post-call pipeline never runs, so the minute ThinnestAI charged us is not metered
     to the client, and the lead and extraction are lost.
  5. `_pipeline_settled` answers `missing_call`, so the poller re-drives the call on every
     tick into the same refusal.

  The same happens to a call that was live on an experiment arm when the experiment was
  concluded.
- **Fix (`c151bb187`).**
  - New `_route_of_call` returns the active route when there is one.
  - Otherwise it returns a route that was retired at or after the call began:
    `updated_at >= started_at`, or `ended_at` when the start is unknown.
  - It never resolves for an account with a `tenant_erasure_requests` row. That check runs
    in the tenant's own session, because the table is FORCE-RLS'd. It keeps the D-189 /
    erasure property that a withdrawn account acquires nothing more.
  - A call that began after its route was retired still raises the existing alarm.
  - Both `_ingest_stages` and `_pipeline_settled` use the new resolver.
  - `_resolve_agent` itself is unchanged, so `tests/tenant_erasure_test.py` keeps asserting
    the erasure withdrawal through it.
- **Tests.** `tests/audit_2026_11_10_z3_test.py`:
  - `test_a_call_taken_before_its_route_was_retired_is_recorded`: FAILED before the fix
    (`'unmapped' == 'pipeline_enqueued'`).
  - `test_the_poller_finds_the_row_of_a_call_on_a_retired_route`: FAILED before the fix
    (`missing_call`).
  - `test_a_call_that_began_after_its_route_was_retired_still_raises_the_alarm`: a guard.
  - `test_an_account_under_erasure_records_no_call_from_a_retired_route`: a guard.

## Verified sound (read at source, not changed)

Earlier rounds already reviewed the voice-runtime intake (sweep 9 sw3, X5); it was re-read
here.

- **Signed intake.**
  - v2 HMAC over `<delivered-at>.<body>`, with a ±5 min window, checked after the
    signature.
  - The event-id header must equal the body `id`.
  - Agent and workspace mismatches are both refused.
  - The secret is chosen by our url's `?agent=`, never by the body.
  - Claim, forensic row and enqueue run in one deadlined transaction. The fast path is
    written only after commit.
- **Upsert.**
  - Status never leaves a terminal state except to `completed`.
  - An unstated status keeps the row's.
  - Erased parties are never refilled.
  - Lost-dial adoption reopens `dial_lost` (X1-01).
- **Engine actions.**
  - Per-agent secret compared in constant time.
  - Workspace header compared.
  - Call identity comes from `X-Call-Id`/`{{call.id}}` and is checked live against
    `GET /calls/{id}` on the same agent.
  - The inbound minimal row uses `ON CONFLICT DO NOTHING`, with an agent match.
- **Caller lookup.** Signed and fresh, active route only, the answer budget held, and a
  repeat answered from the first answer.
- **Workspace routing (D-693).** Publish, number buy and number move refuse
  `workspace_not_provisioned` rather than fall back to the developer workspace. The
  lost-dial search also asks the developer workspace, but by our unique call id, so it
  cannot match another client's call.

## Not fixed

- **Z3-N1 (P2, money; another lane's module, `apps/api/billing/engine_minutes.py`).**
  - The engine minute's rate key is read from the agent's route by
    `ORDER BY r.active DESC, r.updated_at DESC` (`engine_minutes.py:513-523`), not from the
    route the call ran on (`calls` holds no `engine_agent_ref`).
  - So a late call of a retired copy is metered at the agent's CURRENT route's rate key.
    The two can differ when the recreation also changed the voice rung.
  - Before Z3-01 such a call was not metered at all.
  - Fixing it needs the call's own route recorded on the row or the meter (a column or a
    meta read). That is a billing-lane change, so it is reported, not built here.
- **Z3-N2 (P3).** The upsert lets any non-terminal status overwrite another (`in_progress`
  can go back to `ringing`). No producer of a stale non-terminal status was found:
  - only `call.completed` and `call.analysed` are subscribed, and both are terminal;
  - listing rows are the newest try.

  Left alone under "no change that changes nothing".
- **Z3-N3 (P3, UNVERIFIED).** An experiment arm's webhook endpoint is not deleted at
  conclusion, so its late deliveries are refused with 401, and the vendor retries them and
  may switch the endpoint off. Z3-01 makes the poller record those calls, but the signed
  copy of such a delivery is no longer used.
