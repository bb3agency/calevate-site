## Fixed

### Z6-01 (P2): the drift sweep re-armed archived (deleted) agents every half hour
- Where: `apps/workers/engine_reconciliation.py::_reconcile_one`,
  `apps/api/agents/publishing.py::engine_drift_for`, and
  `apps/api/agents/reconciliation.py::claim_drift_batch` (it selects `active` routes only).
- Failure: `lifecycle.archive_agent` (the console's Delete) releases the numbers, retires the
  in-call actions and withdraws the agent's knowledge. It leaves the vendor agent standing,
  and only `experiments.py` and erasure ever set a route inactive, so the route stays active.
  On every tick the sweep therefore claimed the archived agent's route, read it back, rebuilt
  the in-call actions archiving had removed (`check_agent_actions`), repaired its settings
  (`check_agent_settings`, including knowledge on calls) and its voice key, re-pointed its
  caller lookup, and counted it among "live agents" in the drift alarm. That also spent a
  batch slot and vendor round trips that live agents needed. `workers/engine_webhooks.py`
  already treats an archived agent as one we no longer operate.
- Fix: `engine_drift_for` answers `not_published` for an archived agent. The sweep stamps
  that answer, so the route moves to the back of the queue, and then stops: no read-back and
  no repairs. A restored agent is swept again at its next turn.
- Commit: 6b127488b. Test:
  `tests/engine_drift_reconciliation_test.py::test_an_archived_agent_is_left_alone_and_moves_to_the_back_of_the_queue`
  (red before: `checked=1`).

### Z6-02 (P1, call-breaking/compliance): Apply to live could put an unreviewed script live
- Where: `apps/api/agents/publishing.py::apply_to_live`, the pointer UPDATE.
- Failure: the function compares `expected_version` with the draft it read. It then wrote
  `live_prompt_id = system_prompt_id`, guarded only by the two pointers differing. Under READ
  COMMITTED, a draft saved between those two statements still passed the guard, whether by a
  colleague, by Pip's `agent_script_put_live`, or by an autosave put live from another tab.
  The version nobody reviewed was then published to the live phone line, and the response
  reported the checked version number. This is exactly what the docstring's CAS promise rules
  out. `script_publish.put_draft_live` (Put it live) goes through this path.
- Fix: the UPDATE names the checked version. A moved draft gets the existing
  `stale_pending_change` 409.
- Commit: e8892dd75. Test:
  `tests/two_speed_publishing_test.py::test_apply_never_puts_live_a_draft_saved_after_its_check`
  (red before: DID NOT RAISE, unreviewed version applied).

### Z6-03 (P3): Undo could drop a newer draft it never showed
- Where: `apps/api/agents/publishing.py::undo_staged`.
- Failure: Z6-02's race in the other direction. A draft saved after Undo's read was
  discarded from the Script tab, and the answer named the older version as the one
  discarded. History keeps the row, so nothing is lost for good.
- Fix: the UPDATE names the version that was read. A moved draft is refused with
  `stale_pending_change`.
- Commit: 7f93c5c17. Test:
  `tests/two_speed_publishing_test.py::test_undo_never_discards_a_draft_saved_after_its_read`
  (red before).

## Not fixed / unverified
- **Deactivate vs "ready" (design conflict, founder's call).** `lifecycle.deactivate_agent`
  retires the in-call actions "when the agent stops being published". But a paused agent
  that still has an engine agent counts as published ("ready", D-838/D-876,
  `models.is_published`). So the next live apply (`converge_agent`, then `publish_agent`,
  then `_ensure_in_call_actions`) and the drift sweep both put those actions back. This is
  harmless for callers: no number is bound and the dial gate refuses non-live agents.
  However, the two decisions disagree about what a switched-off agent holds. Not changed.
- **Restore leaves a "ready" agent the engine has not got (UNVERIFIED impact).**
  `lifecycle.restore_agent` takes `archived` to `paused` and keeps `engine_agent_ref`, so the
  agent reads as ready at once. Its actions and knowledge were withdrawn at archive, and
  nothing republishes it until the next edit or live apply. The Try it chat would answer
  without knowledge until then. I did not prove this with a test.
- **`live_apply.held_back` after an unproven publish (UNVERIFIED).** A publish whose
  read-back is `unreadable` or `unreachable` writes `live_verified_at = NULL`. `held_back`
  then filters failures with `since = NULL`, so it can show an older live-apply refusal even
  though a later publish went through. I did not prove this.
- Checked and found sound (no change): `publish_agent` serialises on `FOR UPDATE`;
  `queue_live_apply` coalesce and supersede; the worker's cursor, lease and retry ladder;
  the platform revision includes the caller-memory statement version (D-900); the Studio
  `keep_clear_agents_off` / `ensure_studio_in` order; the D-977 pin (the single writer of
  `engine_voice_id` is `lifecycle.update_agent`); `set_voice_tuning` queues for ready agents;
  `check_agent_settings` uses the same config transforms as publish.
