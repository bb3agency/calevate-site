# Deep dive: the HTTP surface, route by route

**Scope**: every mounted route of `apps/api` (204 method+path pairs across 175 paths) and
both routes of `apps/voice-runtime`, their request/response models, and the shared error
ladder. `apps/web`, the billing internals and the engine adapters are other people's
fences; anything found there is reported at the bottom rather than changed.

**Method**: the route list is DERIVED, never typed. Every table below is produced by
walking `rbac.iter_api_routes(app)` and the live OpenAPI schema; the scripts that produced
them are the guardrails this pass leaves behind, so the inventory can be regenerated by
running `make guardrails`. Findings are labelled **PROVEN** (driven over HTTP against the
replay database) or **REASONED** (read, with the mechanism named).

Decisions: **D-300** (error-ladder floor), **D-301** (IDOR sweep completeness),
**D-302** (list bounds), **D-303** (response typing).

## 2. What came back clean

A negative result from a real attempt is evidence, so each of these is stated with what
was actually checked.

- **Authorization (declaration vs enforcement).** All 204 pairs: every non-public route
  declares a permission, the declared permission is one a role actually holds, and the
  dependency tree ENFORCES the same one. Verified by `rbac.assert_policy_registry_complete`
  at boot and re-derived independently for this pass. **No route was found where the
  declared permission and the work done disagree.**
- **Realm pinning.** Every route under `/v1/admin` and `/v1/ops` enforces `realm="admin"`,
  and no admin-realm route lives outside those two path spaces. Already closed in both
  directions by `tests/route_shape_test.py`; re-derived and confirmed.
- **The unauthenticated surface.** 34 routes, every one enumerated with a reason and a
  named credential (`check_public_routes`). Nothing new is exempt.
- **Request validation.** Every request model in the app already sets `extra="forbid"` —
  checked by walking every `body_field` transitively, **zero exceptions found**. Enums are
  closed (`Literal`), ids are typed (`UUID`), and after the `uri` fix every string that is
  STORED carries a `max_length` or a `pattern`.
- **Idempotency.** The four `Idempotency-Key` routes (assist, call-lead, callback, top-up
  intent) all take the claim in its OWN committed transaction BEFORE the side effect, and
  release or complete it in another — the D-181 shape. Campaign launch and KB publish take
  no key and do not need one: launch is a CAS (`WHERE id = :cid AND status IN
  ('draft','scheduled')`) with a discriminating error, and publish detaches-then-attaches
  with an engine-state reconciliation that refuses rather than attaching a second copy.
- **Redaction (hard rule 6).** No phone number appears in any path or query parameter of
  any route; `GET /v1/leads/export.csv` REFUSES `search` for exactly that reason and the
  POST twin exists to carry it in a body. Transcripts default to `text_redacted`; the four
  raw-disclosure routes are role-gated AND audited, verified against the live app by
  `check_redaction_exposure`.
- **Ownership resolution (D-193).** Every client-realm `{id}` route is now driven with a
  neighbour's REAL id and answers 404 — 41 of them, and the completeness of that set is
  now asserted rather than assumed.
- **No dead field in any request contract.** Every field of every request model,
  transitively, is named somewhere in `apps/` — checked by walking each route's
  `body_field` against an AST index of every name, attribute and string constant in the
  tree. Zero fields a caller can set that nothing reads. The two that LOOK dead are
  documented as deliberate and are not: `SubmitIn.uri` (written, never read — there is no
  fetcher yet) and `NumberPurchaseIn.series`/`city`, which are validated and then unused
  because the provisioning adapter does not exist, published now so the shape a client
  codes against does not change on the day it starts working.
- **The one reflected parameter is safe and gated.** `GET /hooks/v1/ingest/meta/{id}`
  echoes `hub.challenge` verbatim, which the Meta handshake requires. It is answered only
  when the presented verify token matches the source's current secret, the response is
  `text/plain`, and the whole URL is bounded by the edge — so it is neither an oracle nor
  an injection surface. Left exactly as it is.
- **Unbounded query strings, re-checked with `pattern` and `Literal` counted as bounds.**
  The first pass flagged twenty; nineteen are bounded by something other than
  `max_length`: `search` is `max_length=60` on the body models and REFUSED as a query
  parameter (`_SEARCH_MOVED_TO_POST` — a phone suffix must not reach an access log),
  `month` is refused by `parse_billing_month` unless it is `YYYY-MM`, `status` is refused
  against the column's own CHECK vocabulary, `columns`/`f` are resolved against the live
  extraction schema, and the calling-window strings carry `pattern=HH:MM`. The twentieth
  was `SubmitIn.uri`, fixed above.
- **`apps/voice-runtime`.** Both routes verify the source before reading a byte, bound the
  body before parsing, measure and report the ack on every exit including refusals, defer
  all work to ARQ, and write no PII to any log line. Nothing was found wrong with the
  order of operations; the only change is the declared ack model.

## 4. Still open (nothing here is codeable in this repo)

- `tests/members_test.py::test_the_last_owner_rule_survives_two_owners_demoting_each_other`
  is **flaky under suite load** — it asserts `[200, 422]` for two owners demoting each
  other concurrently and observed `[200, 403]` once in a full-suite run, then passed
  standalone twice. The 403 is correct behaviour for the loser (it has already been
  demoted and no longer holds `org:manage`); the test's expectation is what is too narrow.
  Reported rather than changed: `members` is the reliability pass's fence, and widening
  another agent's assertion during their session is how two fixes collide.
- **`apps/api/engine/`** holds 15 `ProblemError` sites with no explicit `remediation`
  (bolna, cartesia, fake). They now render the `dependency` floor, which is correct and
  actionable, but a vendor-specific sentence would be better on several of them —
  `engine_capability_unverified` in particular. That module is the engine-adapter fence.
- **`make guardrails` fails on this machine for a reason that is not in this branch.**
  `check_rls_coverage` reports `platform_engine_health: platform-scoped table not in
  RLS_EXEMPT_TENANT_COLUMNS`. That table appears NOWHERE in this worktree — no migration,
  no model — so it reached the shared `calevate_replay` database from a sibling session's
  migration. Every other guardrail passes here, including the two new ones; the check
  reads `pg_catalog`, so it will go green for whoever holds the branch that creates the
  table and its exemption entry. Reported rather than worked around: adding an exemption
  for a table this branch cannot see would be a declaration about somebody else's design.
- **`apps/web`** consumes six of the newly bounded lists. The generated client and the
  OpenAPI snapshot were regenerated in this change (`schema.d.ts` typechecks), so nothing
  is broken; but the screens for members, campaigns, knowledge sources and lead sources
  now have a server-side ceiling of 100–200 rows and no paging control. That is a
  frontend decision, not a backend one.
