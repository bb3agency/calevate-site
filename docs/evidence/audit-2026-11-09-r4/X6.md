## Fixed

### X6-01 (P2) A Pip fill whose field id is a list or an object crashed the stream
- Where: `apps/api/copilot/service.py::validate_fill`, the `field_ids=` list a37c3d2cf added
  to `FillRefusedError`.
- Failure: the model sends `{"field_id": ["open"], ...}` (malformed tool JSON, which the
  function exists to refuse). The item loop refuses it ("one item named no field"), then
  building `field_ids` ran `raw.get("field_id") in by_id`, and a list or dict is unhashable.
  `TypeError` escaped `_run_tool_loop`, which catches only `FillRefusedError`, so the owner's
  Pip answer ended in an error and the model never got the refusal back to repair.
- Fix: the id must be a string before it is looked up.
- Test: `apps/api/copilot/validate_fill_test.py::test_a_field_id_that_is_a_list_or_an_object_is_refused_not_raised`
  (failed with `TypeError: unhashable type: 'list'` / `'dict'` before the fix).

### X6-02 (P2) Two refused fields in one whole part threw away the copy and its profile
- Where: `apps/workers/business_copy.py::_take_out` (9312a3fd8, partial saves).
- Failure: `salvage` hands `_take_out` every refused path of one pass. Two problems in one
  whole part (`starter_words.caution` and `starter_words.topics`, or two `screen_guide`
  fields) took the part out at the first path, and the second hit "already out and still
  refused" and returned False. The whole answer was then refused (`answer_unusable`), the
  capability profile with it, and the run stopped, which the commit exists to prevent.
- Fix: a part already taken out in this pass is skipped. A part out since an earlier pass and
  still refused still ends the salvage, so the loop still terminates.
- Test: `tests/business_copy_e2e_2026_11_09_test.py::test_a_part_refused_in_two_places_is_still_left_out_whole`
  (`salvage` returned None before the fix).

## NOT FIXED (reported)
- P3, first-words name carry (`calevate_shared/engine.py::_PERSON_NAME_FIELD`, 9d62ce0f0).
  It takes "the one word after" the name with no lookahead for a break, unlike
  `call_script._NAME_WITH_TITLE`. An opening like "Hello {{lead_name}} this is Varsha." would
  carry "{{lead_name}} this," onto the next sentence. `script_lint.name_segment_problem`
  refuses that shape on placed-call openings, so only an opening saved without the lint is
  exposed. UNVERIFIED in production. Not edited: engine.py is another lane's file today.
- P3, invitation lock. Each waiting redemption of one link holds a pool connection while the
  winner needs a second one (`credential_session`, the users write). More concurrent presses
  of the same link than the pool size could stall the winner until the pool times out.
  UNVERIFIED (no load test).
- P3, `rates.studio_breakeven_call_minutes`. The scan length is
  `stable_minutes x 540 / chars_per_call_minute`, so a low measured speaking rate (30
  characters a minute is about 41,000 steps per rung) slows the rate card route. It is
  memoized per input. Not measured.
- Product note, not a code defect: under D-976 (no code is sent) an owner can type any
  number, and WhatsApp hot-lead alerts then go to it after their own opt-in. This is the
  founder's decision; `phone_verified_at` is where the later code step lands.
- Out of scope, read only: `script_proposals.request_main_task_fit` and the Latin guard on
  every spoken line in `script_assist.language_problems`. I saw no defect. The guard does
  widen what a script draft can be refused for.
