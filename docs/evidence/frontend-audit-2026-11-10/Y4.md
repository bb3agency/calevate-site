## Fixed

### Y4-01 (P1, dead end): a running campaign stopped for an offer in its agent's script had no way forward
- `campaigns/CampaignStateNotice.tsx:85` used `blockerDestination`, which had no entry for
  `script_promotional`. The "Open the agent" link existed only inside `LaunchGate`. So a campaign
  the dispatcher stops every tick because of D-943 (`campaigns/service.py` `dispatch_blockers`)
  showed "Not calling anyone right now / The agent's script talks about offers." with no button.
- Fix: commit `02e9074f8`. `blockerCopy.fixDestination(rule, at, agentId)` now owns the agent and
  account fixes for any refused dial. `blockerDestination` adds the campaign's own edit page on top
  of it. Both the checklist and the notice pass the campaign's `agent_id`.
- Test: `tests/campaigns.test.tsx` › "gives a running campaign stopped by an offer in its agent's
  script a way to that agent".

### Y4-02 (P2, dead end): a draft refused for `truthful_answer_drift` had no button
- The gate's sentence says "Publishing the agent again restores the rule"
  (`compliance/service.py:646`), but no destination covered the rule.
- Fix: commit `02e9074f8`. The rule links to the campaign's agent ("Open the agent"), or to Agents

- Test: `tests/campaigns.test.tsx` › "gives a draft refused for the truthful-answer rule a way to

### Y4-03 (P2, dead end): a one-off call refused on account grounds showed only a sentence

- Also, "Add credit" went to `/billing`, not `/billing?tab=credits`. Only the `?tab=credits`

- Fix: commit `8baf3b0cf`. `Refusal` uses the same `fixDestination` as campaigns. For a call

- Tests: `tests/makeACall.test.tsx` covers:
  - "gives a %s refusal the button that fixes it", with 5 rules;
  - the updated "sends a refusal for credit to the screen that fixes it…".

## Checked, no defect found
- **Launch checklist:** every rule `launch_blockers` emits now has a fix button, except
  `campaign_archived`, whose Restore is in the page header. This was checked against
  `apps/api/campaigns/service.py:1219-1385` and `account_outbound_blockers`.
- **Contact upload:** bad rows are marked per row ("We can't read this number", "Only Indian (+91)
  numbers are called", duplicate). Only ready rows are sent, and the server's added/duplicate/
  unreadable/outside-India counts are shown (`DraftPeople.tsx`).
- **Duplicate submits:**
  - Make a call holds one Idempotency-Key per attempt.
  - `ActionButton` ignores clicks while pending.
  - The new-campaign flow refuses a second create once a draft exists.
- **Stale status after pause, resume or launch:** the mutations refresh the campaign, the
  campaigns list, the launch check and the attention queue (`lib/api/campaigns.ts:246-279`).
- **Calling-hours wording:** it matches the server's window (09:00-21:00 IST) in Make a call, the
  campaign window refusal and Leads & hours (whose bounds come from the server).

## NOT FIXED
- **P3:** `campaigns/contactList.ts` `normalizePhone` treats only ASCII digits as digits. The
  server (`ingest/service.py:174`) also reads Telugu and Devanagari digits. A CSV written with
  those digits is marked "can't be called" in the browser and never sent, although the server
  would accept it. A correct mirror needs a Unicode decimal-value table. UNVERIFIED that any
  client exports such files.
- **P3, UNVERIFIED reachability:** a RUNNING campaign whose `not_calling` holds a consent
  provenance rule has no answer form. The provenance route accepts only draft or scheduled
  campaigns, by design. Launch requires provenance, so only a campaign launched before the
  columns existed could reach this.
- **P3:** `CampaignStateNotice` reads `BLOCKER_COPY` directly, not through `blockerNote`. A running
  promotional campaign's national-check line would say "We handle this" while the telemarketer
  registration is off. A promotional campaign cannot launch in that state, so this was left alone.
- No 375 px browser pass was run. The fixes add no layout (one optional link and a hidden span).
