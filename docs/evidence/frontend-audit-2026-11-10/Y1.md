## Checked, no defect found
- The "Add a step" inserter can be reached without a mouse: a focused inserter shows through
  `focus-visible:opacity-100`, it responds to Enter and Space, it is never shown above step 1,
  and it is hidden at the step limit (`onInsert` is undefined once `sections.length >= maxSections`).
- After Keep, the Pip suggestion clears (`useClearProposal` writes null to the cache before
  `onKeep`) and Undo is offered. TanStack v5 fires the `mutate` callbacks only for the latest
  call, so a double press keeps the suggestion once. The DELETE is idempotent (204,
  `script_routes.py:1469`).
- "Fix them first" in Put it live (`PutLive.tsx`): the cache is updated before `onFixed`, so
  the builder takes the fixed copy without raising a conflict.

## Not fixed
- `TaughtRules.tsx:93-96`: "Add as a step" appends with `addSection`. A last step that ends
  the call still skips it (the same class as Y1-02). I left it alone because for a behaviour rule,
  "a step after the close" is the wrong place either way. Whether a taught rule should go
  into its role or onto every step is a product decision. Its limit `12` matches
  `MAX_SCRIPT_STAGES` (`call_script.py:410`), but it is a second copy and does not use
  `limits.maxSections`.
- UNVERIFIED: the 375 px layout was not checked in a browser. None of the fixes change layout.
  The moved inserter is absolutely positioned, so it draws in the same place.
- "Add it to my draft" and "Discard" in `PipProposal` show no pending state while the DELETE
  is in flight. This is cosmetic: the request is idempotent and a failure is shown.

No shared files were touched. Tests: the 13 related vitest files pass (228 tests),
`pnpm -C apps/web typecheck` is clean, and eslint is clean on the touched files.
