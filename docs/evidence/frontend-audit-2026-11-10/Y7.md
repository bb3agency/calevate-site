# Y7: admin account management (frontend audit round 5, 10 Nov 2026)

Scope: `app/admin/page.tsx`, `admin/tenants/**`, `admin/new/**`, `admin/view-as/**`,
`admin/holds/**`, `admin/kyc-reviews/**`, `admin/payments/**`, `admin/spend/**`,
`admin/calling-numbers/**`, `admin/operators/**`, and the `lib/api` hooks behind them.
Round 4 lanes W5 and W8 (raw codes, self-links, activity-log notices) were not redone.

All tests: `apps/web/tests/adminAuditY7.test.tsx`. Each failed on the old source.

## Fixed

### Y7-01 (P2): Credits page shows "has not paid yet" and a running trial after the first payment
- `apps/web/src/lib/api/credits.ts` (`useRecordTopUp`, `useRecordRestatement`) and
  `apps/web/src/lib/api/trials.ts` (`useEndTrial`) refreshed only the wallet.
- The server treats a recorded bank transfer, a restatement, and a trial ended as
  `converted` as the account's first payment (`apps/api/billing/credit_routes.py:1372`
  `on_payment_credited`, `apps/api/billing/trial_routes.py:387-390`
  `on_operator_conversion`). It stamps `first_paid_at` and converts a running trial.
- What the operator saw: the Credits page shows `PaidStatusPanel` and `TrialPanel` beside
  the wallet. Both kept saying "has not paid yet" and "running", and kept offering
  "Make paid" and "End trial", until a refocus or remount.
- The fix: one helper, `invalidatePaymentCredited` (wallet + `["admin","paid",id]` +
  `["admin","trial",id]`). Top-up, restatement, end trial and make-paid all use it.
  `useMakePaid` moved onto it, so this is now done one way.
- Commit `48314334a`. Tests: "a payment credited to the wallet" (2 cases), and "ending a
  trial as converted refreshes the paid status beside it".

### Y7-02 (P2): cancelling an invitation took effect on the first click, with no confirmation
- `apps/web/src/app/admin/tenants/[tenantId]/members/InviteRow.tsx:104`: the "Cancel it"
  row-menu item (tone danger, one item below "Wrong address?") called `revoke.mutate`
  directly. One mis-tap killed the owner's live link.
- Every other danger item on these screens asks first: operator revoke, number release,
  number take-back, member removal.
- The fix: a `ConfirmDialog` ("Cancel this invitation?" / "Cancel the invitation" /
  "Keep it") that names the address. Its refusal shows inside the dialog.
- Commit `0f82ef483`. Test: "cancelling an invitation asks before the link stops working,
  and cancels only on the second click".

### Y7-03 (P2): saving commercial terms left the "Capped" state stale everywhere
- `apps/web/src/lib/api/commercials.ts` `useRecordTerms` invalidated only
  `["admin","commercial-terms",id]`.
- `apps/api/billing/terms.py:478-481` re-arms the spend-cap gate (`recompute_capped`) in
  the same transaction, in both directions.
- What the operator saw: the "Capped" pill in the account header (`TenantShell.tsx:130`,
  shown above the Commercials form itself) did not update, and nor did the directory row,
  the ceilings panel (`billing-caps`) or the health board. After tightening or loosening a
  ceiling, the screen showed the old state.
- The fix: the same set `useRecomputeSpendCap` invalidates.
- Commit `69943e79d`. Test: "recording commercial terms refreshes every read that carries
  the spend-cap flag".
