## Not fixed

- **UNVERIFIED design question, not changed: Rights desk "Erase their data" for a view-as
  operator.** The button is enabled from `org:manage` (`useWriteAccess`), while the
  erasure itself is refused by the named act `compliance.erasure_request`. The drawer that
  opens says why and disables the form, so it is not a dead end. Only operators see it,
  never a client member.
- **Root cause is shared (lane Y10).** `components/arc/feedback.tsx::useActionFeedback`
  raises its success toast from an effect. Any caller whose `mutate(..., { onSuccess })`
  unmounts the component holding the hook therefore loses the toast. This lane fixed its
  own call sites by moving the mutation up. A sweep of other lanes' screens for the
  pattern `onSuccess: onDone` / `onSuccess: () => setX(false)` next to a `successToast` in
  the closing child would find the rest. The other option is for the hook to raise the
  toast from the mutation's own `onSuccess`.
- Line protection **Remove** backup phone has no confirmation (one click clears it). This
  is a product choice; it was left alone.
- I did not run a browser check at 375 px. W9 swept every client route at 320/375 two days
  ago. The only new UI here is the shared `ConfirmDialog`, and the a11y sweep
  (`tests/a11y.test.tsx`) passes.
- Read and found sound: the D-976 mobile number row (check-before-save, invalidates `["me"]`
  and the alert state), agreements (`AcceptPanel` sequential accepts), messaging consent
  (lookup reset after a record), quality, performance, D-975 "Name (2)" naming (the toast
  uses the server's returned name).
