## Checked and found sound (not changed)

- **TopUp payment state machine.** It is monotonic (a dismissal after a payment cannot walk
  `verifying` back). A closed window keeps the same order for "Pay now". An unverified
  confirm blocks a second order and says "Do not pay again". Amounts are server strings
  throughout, and `formatPayableINR` is used for payable figures.
- **Platform fee card.** The month just paid has no live Pay button while unverified or
  waiting to land.
- **Own-number purchase.** One request key is used for each confirmation and reused on retry.
  A changed price goes back to the list. Purchase and release invalidate the available list,
  the wallet and the go-live guide.
- **Statement CSV.** Money cells are the server's digits, unguarded and ungrouped. Free text
  is quoted per RFC 4180 and formula-guarded.
- **Spend limit, low-credit email, wallet hero, statements, receipt.** Loading, error and
  empty states are all present. No float reaches a printed figure: `Number()` only sizes bars.
- **Go-live guide.** Each step names its real blocker (OB-1/OB-8/OB-10 already fixed).

## Not fixed (with why)

- **P3, server copy.** The `auto_recharge_over_mandate` remediation says "Lower the recharge
  amount, or approve a new payment method". The panel offers no "approve" for a confirmed
  method, only "Withdraw approval", after which approval is offered again. So the path exists
  but is not the words. The fix belongs in `apps/api/billing/auto_recharge.py:362`, which is
  a backend file outside this lane. Y5-01 removes the usual way into it.
- **P3, design decision.** A "settling" top-up attempt is created by every Continue, even one
  whose window was closed unpaid. It shows "Still settling. Don't pay again yet." for
  `PENDING_GRACE_HOURS`, and the server cannot tell an unpaid closed window from a pending
  payment (`apps/api/billing/wallet.py:489-491`). Changing this needs a product decision on
  the wording, not a bug fix.
- **P3.** `billing/SpendPanel.tsx` prints the raw month in tile labels ("Calling charge ·
  2026-11") where the rest of billing uses `formatBillingMonth`. Readable, so left alone
  (no cosmetic churn).
- **UNVERIFIED.** `billing/CostPerResult.tsx` shows a skeleton for good if the server ever
  returns no window for the selected 7 or 30 days. I did not establish whether the server
  always sends both.
- **Shared, for Y10.** `statementCsv.ts`'s formula guard covers `= + - @` but not a leading
  TAB or CR, which OWASP also lists. Only the server's `ref` text could carry one. It is
  low risk and was not changed.
