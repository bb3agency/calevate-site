## Findings

### E8-01 (P1) Pip background work kept running for a closed or churned account
- Where: `apps/api/tenancy/members.py::acting_member_role` (the predicate a Pip job,
  routine and approved plan run as; used by `copilot/routines._start_job`,
  `workers/copilot_jobs.run_copilot_job`, `workers/copilot_plans._actor`).
- Cause: it asked only "is there a membership and is the person active".
  `core/auth._load_client_principal` refuses every request on an account that is closed
  (`deleted_at`) or churned; queued work never passes through it.
- What went wrong: a routine set up before the account was closed kept firing. Each slot
  queued a job; the job passed consent and fair use, ran Pip's model turns over the
  account's leads and calls, and staged changes for approval. An approved bulk plan kept
  writing. The person themselves is refused at the door, so this is work done "as" them
  that they could not do, on an account whose purpose has ended (it waits for erasure).
  Dialling was already stopped by `account_stopped_blocker` in the dial gate.
- Fix: the query joins `organizations` and refuses `deleted_at IS NOT NULL` or
  `status = 'churned'`, the loader's own predicate. Suspended accounts still run (they
  still sign in; suspension stops dialling only).
- Commit: `aab0d8a93`. **File outside my area, named loudly: `apps/api/tenancy/members.py`**
  (one query and its docstring). It is the one predicate the three Pip background runners
  share, so the fix is there rather than in three copies.
- Tests (`tests/journey_audit_e8_test.py`):
  - `test_background_work_does_not_act_for_an_account_that_has_ended[closed|churned]`
  - `test_a_closed_account_s_queued_job_makes_no_model_call` (red on base: the model stub
    was called)
  - `test_a_churned_account_s_routine_starts_no_job` (red on base: `queued`)
  - `test_a_suspended_account_s_background_work_still_runs` (guards the other half)

### E8-02 (P1) Pip could write to a deleted agent that the screen refuses
- Where: `apps/api/copilot/write_tools.py::_refuse_a_deleted_agent`, and `confirm` /
  `approve` in the same file.
- Cause, two parts:
  1. The route guard (`agents/write_guard.guard_agent_write`, from `requires()`) refuses
     any write whose path names an `{agent_id}` of a deleted agent, whatever the route
     records. Pip's guard ran only for tools whose `object_type` is `agent`.
     `agent_test_add` records an `agent_test_case`, so Pip saved a test on a deleted agent
     that `POST /v1/agents/{agent_id}/test-cases` refuses with `agent_archived`.
  2. The guard ran when a card was drawn or a change staged, not when it ran. An approval
     waits up to `action_log.APPROVAL_TTL` (24 hours); approving a change a routine
     staged before the agent was deleted ran it (the planner does not re-check).
- Fix: `_assert_agent_args_writable` keys on an `agent_id` argument for every tool (except
  `acts_on_archived`, i.e. `agent_restore`). `_refuse_a_deleted_agent` wraps it for the
  model; `approve` runs it before re-planning (a deleted agent decides the approval as
  refused, `applied: false`); `confirm` runs it before the burn (409 `agent_archived`, the
  route's own refusal and wording).
- Commit: `cd7e4877c`.
- Tests: `test_pip_cannot_add_a_test_to_a_deleted_agent` (red on base: did not raise),
  `test_an_approval_waiting_on_an_agent_deleted_since_does_nothing` (red on base:
  `applied=True`, the test was saved).
